# Codex Exec Plan

## 概要

ExecPlan方式で長時間タスクの計画と実装を進めるための手順を示す。計画の作成と実行を分離し、PLANS.mdの規約に沿った自己完結な計画書を作成・維持する。

## ワークフロー

### 1. トリガーと前提確認

 - ユーザーの依頼が「計画を立ててください」の表記ゆれ（例: 計画を立てて, 計画を立てて下さい, 計画立てて）を含む場合に発動する。
- 依頼対象が曖昧な場合は、最小限の確認質問だけ行う（対象機能、制約、期限/優先度）。

### 2. リポジトリ整備

- `AGENTS.md` を確認し、`ExecPlans` セクションが無ければ追記する。
- `.agent/PLANS.md` が無ければ作成し、`references/exec_plan_reference.md` の内容を反映する。
- 既存の `.agent/PLANS.md` がある場合は、その方針を優先し、必要なら不足要素のみ追加する。

### 3. ExecPlan作成

- ExecPlanはPLANS.mdの規約に従って作成する。ファイル名はユーザー指定に従い、指定がなければ新規のMarkdownとして作る。
- PLANS.mdのスケルトンに従い、すべての必須セクションを埋める。
- 作成前に `.agent/PLANS.md` を全文で読み、書式と要件を厳密に守る。
- 文章は日本語で書く。専門用語は都度定義する。
- コマンド、パス、確認方法は具体的に書く。検証手順と期待結果を必ず入れる。
- 進捗は `Progress` にチェックリスト + タイムスタンプで記録する。
- チャットで提示する場合は単一の ```md フェンスで出力し、ファイル書き出し時はフェンスを省略する。

### 4. 実行モード

- ユーザーが実行を求めた場合は、ExecPlanに沿って実装を進め、停止点ごとに `Progress` / `Decision Log` / `Surprises & Discoveries` を更新する。
- 「次のステップは?」と聞かず、次のマイルストーンへ進む。
